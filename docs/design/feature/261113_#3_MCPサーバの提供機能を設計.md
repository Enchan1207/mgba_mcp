# MCPサーバで提供する機能の設計

## 1. 目的と対象範囲

[issue #11「MCPサーバで提供する機能を決める」](https://github.com/Enchan1207/mgba_mcp/issues/11)に向け、エージェントがゲームを操作して画面を確認するためのMCPツールを定義する。公開するツールは`press_button`、`walk_for`、`wait`、`get_screen`の4つとする。

## 2. 全体構成

`mgba_mcp`はMCPクライアントから標準入出力で要求を受け、Unix domain socketを介して`mgba_server`に接続する。操作と画面取得には1本の`CONTROL`接続を使う。`mgba_server`のコマンド体系は[コマンドリファレンス](../../server/command_references.md)に従う。

`walk_for`でボタンを解放した後に進めるフレーム数はMCPサーバの設定値とし、初期値を10とする。

## 3. 公開インターフェース

### 3.1 `press_button`

- 入力
  - `button`: `A`、`B`、`SELECT`、`START`、`RIGHT`、`LEFT`、`UP`、`DOWN`のいずれか。
  - `frames`: ボタンを押すフレーム数。省略時は10。
- 動作
  - 指定ボタンを`frames`フレーム押す。全ボタンを解放し、同じ`frames`フレーム進める。

### 3.2 `walk_for`

- 入力
  - `direction`: `UP`、`DOWN`、`LEFT`、`RIGHT`のいずれか。
  - `frames`: 方向キーを押すフレーム数。
- 動作
  - 指定方向を`frames`フレーム押す。全ボタンを解放し、設定されたフレーム数だけ進める。
  - 実際の移動距離は保証しない。

### 3.3 `wait`

- 入力
  - `frames`: 無入力で進めるフレーム数。
- 動作
  - 全ボタンを解放してから、無入力で`frames`フレーム進める。

### 3.4 `get_screen`

- 入力
  - なし。
- 動作
  - 現在の公開画面をPNG画像で返す。
  - 画面がない場合は全ボタンを解放し、1フレーム進めてから取得する。

### 3.5 入力制限と戻り値

`press_button`、`walk_for`、`wait`の`frames`は1～18000の整数とする。`walk_for`の解放後フレーム数にも同じ範囲を適用する。

操作ツールは、今回進んだフレーム数`framesAdvanced`と操作後の累積フレーム数`totalFrames`を返す。操作結果に画像は含めない。`press_button`の`framesAdvanced`は`2 × frames`、`walk_for`は押下フレーム数と解放後フレーム数の合計、`wait`は指定したフレーム数とする。

`get_screen`はPNG画像、今回進んだフレーム数`framesAdvanced`、画像の累積フレーム数`totalFrames`を返す。既存の画面を取得した場合、`framesAdvanced`は0とする。画面を生成するために1フレーム進めた場合、`framesAdvanced`は1とする。

## 4. サーバとの通信と状態管理

### 4.1 接続と応答

接続後に`HELLO CONTROL`を送り、成功応答を受けてからコマンドを送る。同じ接続では要求と応答を一つずつ処理する。コマンドの応答形式、画像本文、エラーコードは[コマンドリファレンス](../../server/command_references.md)に従って解析する。

### 4.2 コマンド変換と状態

- `press_button`
  - `RELEASE ALL` → `TYPE <button> <frames>` → `STATUS`
- `walk_for`
  - `RELEASE ALL` → `PRESS <direction>` → `STEP <frames>` → `RELEASE ALL` → `STEP <解放後フレーム数>` → `STATUS`
- `wait`
  - `RELEASE ALL` → `STEP <frames>` → `STATUS`
- `get_screen`
  - `CAPTURE`を送る。`NO_FRAME`なら`RELEASE ALL` → `STEP 1` → `CAPTURE`を送る。

操作ツールが成功した後は、全ボタンが解放されている。`totalFrames`には最後の`STATUS`の値を使う。`get_screen`の累積フレーム数には`CAPTURE`の画像本文に含まれる値を使う。RGBX8888の画像本文は寸法と長さを検証してからPNGに変換する。

### 4.3 失敗時の扱い

複数コマンドから成る操作が途中で失敗した場合、可能なら`RELEASE ALL`を送る。解放できたか確認できない場合や、実際に進んだフレーム数を確定できない場合は、その状態をエラーとして伝える。接続が切れた場合は保持していた接続を破棄し、次の要求で接続を試みる。

## 5. 検証方針

- 各ツールの入力値、フレーム数の範囲、省略時の値を確認する。
- `press_button`、`walk_for`、`wait`のコマンド順、進んだフレーム数、操作後のボタン解放を確認する。
- 画面取得時のPNG変換、画像本文の検証、画面がない場合の1フレーム実行を確認する。
- `CONTROL_BUSY`、`NO_FRAME`、接続断、操作途中の失敗を確認する。
