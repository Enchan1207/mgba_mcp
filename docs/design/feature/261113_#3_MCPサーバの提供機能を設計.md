# MCPサーバで提供する機能の検討

## 対象と出典

- [issue #11「MCPサーバで提供する機能を決める」](https://github.com/Enchan1207/mgba_mcp/issues/11) は、mGBA サーバのコマンドをエージェントが遊びやすいインタフェースに変換することを求めている。
- [issue のコメント](https://github.com/Enchan1207/mgba_mcp/issues/11#issuecomment-6844001076) は、ポケモンを念頭に操作系4つ・観測系4つを提案し、初期実装として `press_button`、`walk_for`、`wait`、`get_screen`、`get_party` の5つを挙げている。これは提案であり、確定仕様ではない。
- このファイル名の `#3` と、このブランチが対象とする issue `#11` は異なる。設計の対象は `#11` とする。

## 現状から分かること

- `mgba_mcp` は stdio の MCP サーバとして起動するが、ツールはまだ登録されていない。
- `mgba_server` は Unix domain socket で `CONTROL` 接続を一つだけ許す。操作には `PRESS`、`RELEASE`、`TYPE`、`STEP`、`RESET`、`READ`、観測には `STATUS`、`CAPTURE` を使える。
- `TYPE <button> <frames>` は指定ボタンを `frames` フレーム押し、解放して同じ `frames` フレーム進める。計 `2 × frames` フレーム消費し、他の押下中ボタンは維持される。
- `STEP <frames>` は現在の押下状態のまま進む。`CAPTURE` は最初の `STEP` 前と `RESET` 直後には `NO_FRAME` を返す。
- `READ` は生の Game Boy バス値を返す。手持ちなどの意味づけには対象 ROM ごとのメモリ配置とデータ形式が必要だが、このリポジトリにはまだ定義がない。

## 機能候補と実現方法（暫定）

| 公開ツール | 実現方法 | 設計上の注意 |
| --- | --- | --- |
| `press_button(button)` | 短い `TYPE`、または `PRESS` → `STEP` → `RELEASE` | 押下期間と解放後のフレーム数を固定・明記する。既に同じボタンが押されている場合の扱いも決める。 |
| `walk_for(direction, frames)` | `PRESS` → `STEP` → `RELEASE` | `frames` は押下期間と定義する。移動距離は保証しない。途中失敗時にも押下を解除する。 |
| `wait(frames)` | 押下状態を確認・解放して `STEP` | 無入力を保証するなら `STEP` 単体では足りない。既存の押下状態をどう扱うか決める。 |
| `get_screen()` | `CAPTURE` の RGBX8888 を PNG に変換 | 画像と経過フレーム数を返す。`NO_FRAME` を明確な結果として扱う。 |
| `get_party()` | 対象 ROM の形式に従って `READ` を解釈 | 対応作品・バージョンの特定、アドレス検証、テスト用 ROM または固定データが必要。 |

操作結果は `framesAdvanced` と `totalFrames` を共通で返す案を採る。`totalFrames` は操作後の `STATUS` を正とし、`RESET` では 0 に戻る。操作結果に画像は含めず、必要な時だけ `get_screen` を呼ぶ。複数コマンドから成る操作の途中で失敗した場合は、成功した部分のフレーム数を正確に返せるか、状態不明のエラーとするかを決める。

## 検討したい判断

1. 初期対象のゲームと ROM の版は何か。`get_party` を初期スコープに入れるには、この情報が必要。
2. `press_button` の押下・解放後フレーム数はいくつにするか。方向キーも受け付けるか。
3. `walk_for` は解放後に追加フレームを進めるか。進めるなら戻り値にその数をどう示すか。
4. MCP が操作した後は常に全ボタンを解放する契約にするか。その契約なら `wait` の無入力を保証しやすい。
5. `get_screen` の `NO_FRAME` 時には、初期フレームを自動で進めるか、画像なしを返すか。

`reset`、`get_battle_state`、`get_player_state` は次段階の候補。`get_bag`、`get_pokedex`、`get_map`、`get_game_flags` はさらに後の候補とし、公開する情報の範囲を個別に決める。
