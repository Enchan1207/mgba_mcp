# mGBA サーバ コマンドリファレンス

接続・起動の手順は [サーバへの接続](connection.md) を参照してください。

## 要求と応答

要求は改行（`\n`）で終わる一行です。改行を含む上限は 32 バイトです。コマンド名と引数は ASCII で記述し、英字の大文字・小文字は区別しません。フレーム数と待機時間は十進整数です。役割宣言後は要求一つにつき応答を一つ返します。不正な要求には `BAD_REQUEST` を返し、上限を超える要求行では接続を閉じます。

応答は以下の順に並ぶバイト列です。本文長は最大 1 MiB です。

| 順序 | 内容 | 長さ |
| --- | --- | --- |
| 1 | 結果: 成功 `S`、エラー `E` | 1 バイト |
| 2 | 本文長: リトルエンディアン `uint32_t` | 4 バイト |
| 3 | 本文 | 本文長のバイト数 |
| 4 | 終端 `\n` | 1 バイト |

受信側は各部分を指定長だけ読み切り、本文長が 1 MiB 以下で終端が `\n` か確認してください。エラー本文は ASCII のエラーコードです。本文のない成功応答は `S\x00\x00\x00\x00\n` です。

### 状態本文

`STATUS` の成功本文は ASCII の次の形式です。末尾に改行は含みません。

```text
frames=<uint64> pressed_keys=<uint32> has_frame=<true|false>
```

`frames` は経過フレーム数、`pressed_keys` は入力ビットマスクの十進数、`has_frame` は公開画面の有無です。

### 画像本文

`CAPTURE` と `WAIT_FRAME` の成功本文は次の形式です。

| 順序 | 内容 | 長さ |
| --- | --- | --- |
| 1 | 経過フレーム数: リトルエンディアン `uint64_t` | 8 バイト |
| 2 | 幅 | 1 バイト |
| 3 | 高さ | 1 バイト |
| 4 | RGBX8888 画素列、行優先 | 幅 × 高さ × 4 バイト |

画素は `R, G, B, X` の順で、`X` は 0 です。現在の画面は 160 × 144 ピクセルで、画像本文は 92,170 バイトです。受信側は本文長と寸法の整合性を確認してください。

## コマンド

| コマンド | 役割 | 成功時の本文 | 動作 |
| --- | --- | --- | --- |
| `HELLO CONTROL` / `HELLO VIEW` | 接続直後 | なし | 接続の役割を宣言する |
| `PRESS <button>` | `CONTROL` | なし | ボタンを押下状態にする |
| `RELEASE <button>` / `RELEASE ALL` | `CONTROL` | なし | ボタンの押下状態を解除する |
| `TYPE <button> <frames>` | `CONTROL` | なし | ボタンを押して指定フレーム進め、離して同じフレーム数進める |
| `STEP <frames>` | `CONTROL` | なし | 1～18000 フレーム進め、最終画面を公開する |
| `READ <address> <length>` | `CONTROL` | 読み出したバイト列 | 指定したアドレスから現在のメモリを読み出す |
| `RESET` | `CONTROL` | なし | 入力・経過フレーム数・公開画面を初期化する |
| `STATUS` | `CONTROL`, `VIEW` | 状態本文 | 現在の状態を返す |
| `CAPTURE` | `CONTROL`, `VIEW` | 画像本文 | 現在の公開画面を返す |
| `WAIT_FRAME <timeout_ms>` | `VIEW` | 画像本文 | 1～120000 ミリ秒まで画面状態の更新を待つ |
| `QUIT` | `CONTROL` | なし | サーバの終了処理を始める |

`button` は `A`, `B`, `SELECT`, `START`, `RIGHT`, `LEFT`, `UP`, `DOWN` のいずれかです。`RELEASE` のみ `ALL` も指定できます。

`TYPE` の `frames` は各段階で進めるフレーム数（1～18000）です。たとえば `TYPE A 10` は `PRESS A`、`STEP 10`、`RELEASE A`、`STEP 10` と同等で、合計 20 フレーム進みます。ほかのボタンの押下状態は維持されます。画面状態は各 `STEP` 後に更新されます。

`READ` の `address` は 1～4 桁の 16 進数（`0000`～`FFFF`、接頭辞なし）、`length` は 1 以上の十進数です。`address + length` は `10000` (16 進数) 以下でなければなりません。成功本文はコマンド実行時点の Game Boy バスから読み出した `length` バイトそのものです。数値文字列やアドレスなどのヘッダは付けません。

`CAPTURE` は応答時点の画面を返し、その接続の通知済み更新番号を記録します。画像がない場合も番号を記録して `NO_FRAME` を返します。

`WAIT_FRAME` は通知済み更新番号が未設定なら現在の画面状態を直ちに返します。以後は `STEP`、`TYPE` または `RESET` による更新を待ちます。`RESET` の更新では `NO_FRAME` を返し、通知済み番号を進めます。時間切れの `TIMEOUT` では通知済み番号を維持します。

## エラーコード

| コード | 発生条件 | 接続 |
| --- | --- | --- |
| `BAD_REQUEST` | 構文・引数・役割宣言が不正 | コマンドでは継続、役割宣言では終了 |
| `FORBIDDEN` | 接続の役割ではコマンドを実行できない | 継続 |
| `CONTROL_BUSY` | `CONTROL` 接続が既に存在する | 終了 |
| `NO_FRAME` | `CAPTURE` または `WAIT_FRAME` で画像がない | 継続 |
| `TIMEOUT` | `WAIT_FRAME` の待機時間が経過した | 継続 |
| `SERVER_SHUTDOWN` | サーバ終了中の `WAIT_FRAME` | 終了 |
| `INTERNAL_ERROR` | 応答作成前にサーバ内部の処理に失敗した | 終了 |
